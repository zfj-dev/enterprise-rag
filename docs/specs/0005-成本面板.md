# Spec 0005 — 成本面板（per-query 用量/费用 + 预算上限）

> 词汇遵循 [CONTEXT.md](../CONTEXT.md)。
> 对应 [ROADMAP.md](../ROADMAP.md) 的 **Q9i**（顺序 #5 的第一半）。
> 发布目标：GitHub issue，标签 `ready-for-agent`。

## Problem Statement

作为项目作者，我**不知道每次问答花了多少钱**：

- 系统从不记录 token 用量——云端 LLM 明明在响应里返回了 usage，**现在被直接丢掉**。
- 我没有任何地方能看到**累计成本**，也无法把它**按人分摊**。
- 于是三个问题都答不了："这个问题值不值这个价"、"是谁在用、用了多少"、"现在一天烧掉多少"。
- 更关键的是**刹不住车**：一旦某个超长文档被反复检索、或某个账号被刷，我只能等账单出来才知道。

而这个盲区**正在变大**：Spec 0002 的代理会让一次问答变成多步调用，Spec 0003 的摘要会额外增加调用——**调用次数要成倍上升，没有计量就是盲开**。

## Solution

给每次生成记一笔**用量与费用**，并提供**可见性**与**上限**：

- 每次生成记一条用量记录：**输入 / 输出 token、模型、口径来源、折算费用**。
- **管理员看全局，用户看自己**。
- **预算上限**：按用户、按自然窗口累计**费用**；到达上限后**拒绝该用户的新问答请求**（明确的状态码与原因），**已在进行中的流不被打断**。
- token 口径**优先用 provider 返回的 usage**（真实计费口径），拿不到才回退本地分词器，并**标出这笔数字的口径来源**。

## User Stories

1. 作为项目作者，我想知道**每次问答花了多少 token 和多少钱**，以便判断这个问题的成本是否合理。
2. 作为项目作者，我想看到**累计成本**，以便知道这个系统一天/一月烧掉多少。
3. 作为项目作者，我想看到成本**按人分摊**，以便知道是谁在用、用了多少。
4. 作为项目作者，我想让 token 数字**优先来自 provider 返回的 usage**，以便它与真实账单一致。
5. 作为项目作者，我想在拿不到 usage 时**回退本地计数**，以便仍有可用的数字。
6. 作为项目作者，我想在记录里**看到这笔数字是哪种口径**，以便不会把估算当成账单。
7. 作为项目作者，我想在**两种口径都拿不到**时看到"不可用"，以便不会拿到一个静默编出来的 0。
8. 作为项目作者，我想按**费用**（而非 token）设上限，以便跨模型可比、换模型后上限仍有意义。
9. 作为项目作者，我想给每个用户设**预算上限**，以便一个人不能把额度烧光。
10. 作为项目作者，我想让预算按**自然窗口**（日/月）滚动，以便它对"这个月还剩多少"有意义。
11. 作为项目作者，我想在超预算时**拒绝该用户的新请求**并给出明确原因，以便真正刹住成本。
12. 作为项目作者，我想让**已在进行中的流不被打断**，以便用户不会拿到半个答案。
13. 作为项目作者，我想让**管理员豁免硬拦**，以便我不会把自己锁在系统外面。
14. 作为项目作者，我想让**未知模型的单价被显式标注**（而不是默认按 0 算），以便数字不会悄悄失真。
15. 作为项目作者，我想用**可配置的价格表**覆盖内置单价，以便供应商调价时不用改代码。
16. 作为使用者，我想看到**自己的**用量与费用，以便知道自己的额度还剩多少。
17. 作为使用者，我想**看不到别人的**用量，以便不泄露他人使用情况。
18. 作为使用者，我想在被限流时收到**清楚的说明**（而不是一个莫名的报错），以便知道是额度用完了。
19. 作为项目作者，我想让成本记录**挂在已有的 per-query trace 上**，以便不新开一条观测通道、排障时一处看全。
20. 作为项目作者，我想让成本统计**复用已有的指标接口**，以便管理端不用新学一套入口。
21. 作为项目作者，我想让统计**在演示/Fake 模式下也成立**（Fake 也有 token 与单价），以便离线也能演示这套计量。
22. 作为项目作者，我想让成本功能**有开关**，以便出问题能一键退回（退回后不再拦、不再记账）。
23. 作为面试官 / 招聘方，我想看到**成本可见 + 有上限**，以便判断候选人有生产意识而非只会跑通 demo。
24. 作为企业使用方，我想知道**额度用尽时会明确拒绝而不是继续烧**，以便成本可控。

## Implementation Decisions

### 组件边界

- **用量记录器**：从外部注入；每次生成完成后记一条用量记录。
- **价格表**：模型 → 单价（区分输入 / 输出），**可配置覆盖内置值**。
- **预算判定**：一个**纯函数**（用户 + 自然窗口内累计费用 vs 上限），无副作用、可确定性测试。

### token 口径（优先级 + 必须标注来源）

- **优先使用 provider 返回的 usage**（真实计费口径）。
- 拿不到时回退**本地分词器**——**复用 Spec 0003 已建立的分词器缝**，不另造一套计数。
- 两者都拿不到时，该笔记录标记为**不可用**，**不得静默记 0**。
- **每条记录都标注口径来源**，使"这是账单"与"这是估算"不会被混为一谈。

### 计量单位与价格

- 记录输入 / 输出 token，并按模型单价**折算费用**。
- **预算以「费用」为口径**（不是 token），这样跨模型可比、换模型后上限仍然有意义。
- 未知模型必须**显式标注"单价未知"**，**不得默认按 0 计算**——否则数字会随时间静默失真。

### 预算与硬拦（边角在此写死）

- **粒度**：按**用户** + 按**自然窗口**（日 / 月，可配）累计。
- **判定时机**：**生成开始前**（鉴权之后、调用 LLM 之前）——所以判定依据是**此前已累计**的用量（本次请求的用量在完成后才入账）。
- **超限动作**：拒绝该用户的**新**问答请求，返回明确的状态与原因文案。
- **流中不打断**：**已在进行中的流照常走完**，拦截只对**下一个**请求生效——避免用户拿到半个答案。
- **管理员豁免硬拦**：管理员不受拦截（避免运维把自己锁在系统外），但其用量**照常记录与展示**。

### 可见性

- **管理员**看全局聚合（总额、按用户、按窗口）。
- **普通用户**只看**自己**，看不到他人用量。
- 复用**已有指标接口**作为入口，不新起一套；成本挂在**已有的 per-query trace** 上。

### 开关与兼容

- 有配置开关；关闭时**不再记账、不再拦截**，行为与今天完全一致。

## Testing Decisions

- **好测试的标准**：只测**外部行为**（记了什么、拦了谁、谁能看见什么），不测实现细节。
- **缝**（一处新增 + 一处复用）：
  1. **新增**：用量记录器与价格表——注入 **stub 价格表 + stub 用量来源**，全程无网络、无真实 LLM。
  2. **复用**：**Spec 0003 的分词器缝**（本地回退口径）——不再新造计数能力。
- **将测的模块**：
  - **口径优先级**——有 provider usage 时用 usage 并标注；无则用本地并标注；**两者皆无时标记不可用**（断言**不会记成 0**）。
  - **费用折算**——已知单价折算正确；**未知单价显式标注**而不是按 0 算。
  - **预算判定（纯函数）**——窗口内累计、**恰好等于上限**的边界、超限三种情形。
  - **硬拦行为**——超限时新请求被拒且原因明确；**已开始的流不被打断**；**管理员豁免**且其用量仍被记录。
  - **可见性**——普通用户只能看到自己的用量；管理员能看到全局聚合。
  - **开关**——关闭时不记账、不拦截。
- **测试先例**：`tests/test_stream_limit.py`（已有的每用户 SSE 限流测试，与本 spec 的"按用户拦截"最接近）、`tests/test_api_inference.py`（在边界类注入 stub、不联网）。

## Out of Scope

- 与 provider **账单的真实对账**（本 spec 只保证口径标注清楚）。
- **自动降级到更便宜的模型**或成本优化建议。
- 多租户计费、发票、支付、充值、配额购买。
- **图表与趋势可视化**——本 spec 只要求数字**可见**（管理端与个人端各有接口与展示），图表另议。
- 按知识库 / 按会话的预算（本 spec 的预算只按用户 + 时间窗口）。
- 多代理 / 微调 / 多模态 / CRUD-RAG。

## Further Notes

- **与 Spec 0003 的关系**：**复用其分词器缝**，避免出现两套互相矛盾的 token 计数；0003 的上下文压缩会直接降低 prompt token，而本 spec 正好是**量化那次压缩收益**的工具。
- **与 Spec 0002 的关系**：代理的多步调用会显著抬高调用次数与成本，本 spec 是其**成本量化的前提**（但不依赖其实现，可先行）。
- **价格表会过期**：因此把"口径 + 未知单价显式标注"写成硬要求，而不是靠维护一份永不过期的价目表。
- **硬拦是明确选择的强约束**：其边角（流中不打断、管理员豁免、判定时机在生成前、窗口滚动）已在上文**写死**，实现时不得含糊——否则"预算上限"会变成一句空话。
- **发布**：本环境无 `gh`，spec 先落 `docs/specs/`；作者在本机 `gh` 登录后 `gh issue create` 发布并打 `ready-for-agent` 标签（同 0001–0004）。
