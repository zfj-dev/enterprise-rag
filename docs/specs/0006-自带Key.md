# Spec 0006 — 自带 LLM Key（BYOK，自动适配）

> 词汇遵循 [CONTEXT.md](../CONTEXT.md)。
> 对应 [ROADMAP.md](../ROADMAP.md) 的 **Q9ii**（顺序 #5 的第二半；取代已放弃的"一键私有化部署"）。
> 发布目标：GitHub issue，标签 `ready-for-agent`。

## Problem Statement

作为项目作者，系统的 LLM 是**全局写死在配置里**的：所有人共用同一个 provider、同一个 key、同一个模型。三个后果：

- 身边人想用**自己顺手的模型**（或用自己的额度）时我做不到——只能改配置、重启服务。
- **所有人的成本都记在我的 key 上**，没法分摊（Spec 0005 只能事后归因，不能把钱分出去）。
- 我想试一个新厂商 / 新版本，就得改代码或环境变量，**试错成本高**，于是懒得试。

而"6G 显存跑不动本地大模型"这个硬件约束还在（见 README），所以多模型能力**只能靠让用户自带 key**，不可能靠本地多部署几个模型。

## Solution

让用户**自带 LLM Key（BYOK）**：

- 用户填入自己的 `base_url` / `key` / `model`，系统按 **OpenAI 兼容协议自动适配**——**不改代码就能换模型**。
- key **加密落库**、跨会话复用、**从不回显**（只显示尾号），可轮换、可删除。
- **能力探测**：探测该模型的能力（上下文窗口、**是否支持 tool-calling**），供代理链路（Spec 0002）判断能否使用并**优雅降级**——否则用户接一个不支持工具的模型，代理会当场坏掉。
- BYOK 用量**照常记账可见**，但**不纳入项目方的预算硬拦**（用户花的是自己的钱）；**余额提醒尽力覆盖**——厂商能查余额就展示真实余额并提醒，查不到就**明确告知"该厂商不支持余额查询"**。
- 用户**没配** BYOK 时，回落到服务端全局 LLM —— 即今天的行为。

## User Stories

1. 作为使用者，我想填入**自己的 LLM key 与模型**，以便用我顺手的模型而不是平台默认的。
2. 作为使用者，我想只填 `base_url` / `key` / `model` 三样就能用，以便不必研究各家 SDK 的差异。
3. 作为使用者，我想**不改代码就能换模型**，以便随时在新厂商与新版本之间切换。
4. 作为使用者，我想让 key **存一次就一直有效**，以便不用每个会话重填。
5. 作为使用者，我想 key **永远不被回显**（只看到尾号），以便即使界面被人看到也不泄漏。
6. 作为使用者，我想能**轮换或删除**我的 key，以便 key 泄漏或不再使用时能收回。
7. 作为使用者，我想知道**我配的模型能不能用**（连通性），以便不用等提问失败才发现填错。
8. 作为使用者，我想知道**我的模型支不支持工具调用**，以便理解为什么代理功能对我不可用。
9. 作为使用者，我想在模型不支持工具时**优雅降级**（仍能正常问答），而不是直接报错。
10. 作为使用者，我想**看不到别人的 key 配置**，以便我的凭据不被他人知晓。
11. 作为使用者，我想用 BYOK 时**不被平台预算法拦**，以便花自己的钱时不受平台额度限制。
12. 作为使用者，我想在**用量接近我的额度**时收到提醒，以便避免在不知情的情况下超额。
13. 作为使用者，我想**随时切回平台的 LLM**，以便自己的 key 出问题时还能用。
14. 作为项目作者，我想让 BYOK **按用户隔离**，以便一个人的配置不影响别人。
15. 作为项目作者，我想让 BYOK **只影响生成**（嵌入/重排仍是服务端的本地 bge），以便检索质量不因用户配置而漂移。
16. 作为项目作者，我想让 key **加密落库**，以便数据库被看到时凭据不直接可用。
17. 作为项目作者，我想让**日志与 trace 里永不出现明文 key**，以便排障时不会顺手泄漏。
18. 作为项目作者，我想**禁止用户把 `base_url` 指向内网/回环地址**，以便不被人用我的服务当内网跳板（SSRF）。
19. 作为项目作者，我想让能力探测结果**被缓存**，以便不为每次问答都做一次探测。
20. 作为项目作者，我想在探测失败时**按保守默认处理并标注**，以便不会因为探测不到就贸然启用代理。
21. 作为项目作者，我想让 BYOK 用量**接入 Spec 0005 的记账**（可见、可审计），以便成本仍然一处看全。
22. 作为项目作者，我想让 BYOK **有开关**，以便出问题时一键退回"全部走服务端全局配置"。
23. 作为面试官 / 招聘方，我想看到**加密存储、不回显、私网禁入**三件事都做了，以便判断这是有安全意识的实现。
24. 作为企业使用方，我想知道**凭据不会被平台方滥用或泄漏**，以便放心把自己的 key 填进来。

## Implementation Decisions

### 组件边界（三者都从外部注入）

- **LLM 工厂**：`用户配置 → LLM 实例`。默认实现返回服务端全局实例，使"未配置 BYOK"的路径零变化。
- **Key 加密存储**：按用户存取与删除凭据；默认内存实现，便于测试隔离。
- **能力探测器**：探测模型的上下文窗口与工具调用能力；默认返回**保守默认**。

### 架构改动（本次最主要的一处）

- LLM 从**全局单例**改为**按请求解析**：请求开始时，按发起用户解析出应当使用的 LLM（用户的 BYOK 配置，或回落到服务端全局配置）。
- **硬要求**：未配置 BYOK 时，行为与今天**完全一致**。

### 作用域

- **按用户隔离**；且 BYOK **只影响生成**——嵌入与重排仍是服务端的本地 bge，检索质量不因用户配置而漂移。

### 协议与自动适配

- 按 **OpenAI 兼容**协议调用，**复用现有客户端**，不为各家新写适配器。
- 用户只提供 `base_url` / `key` / `model` 三项。
- **能力探测**：探测**上下文窗口**与**是否支持 tool-calling**；结果**缓存**（不为每次问答重复探测）；探测失败时按**保守默认**处理并**标注**——**不得默认"支持工具"**。

### 代理降级（与 Spec 0002 的接合点）

- 当模型**不支持 tool-calling** 时，代理链路**降级为单步回答**，**不得报错**，并在界面上说明原因。

### Key 安全（三条硬线）

- **加密落库**：加密密钥来自服务端配置，**不得有默认弱值**（沿用现有"真实模式强制强 SECRET_KEY"的做法）。
- **从不回显**：读取接口只返回尾号等非敏感信息，**任何响应都不含明文 key**。
- **日志与 trace 永不出现明文 key**。
- 支持**轮换**与**删除**；删除后立即回落到全局配置。

### base_url 防护（SSRF）

- 强制 **https**（本地开发场景可显式放行）。
- **禁止指向私网 / 回环 / 链路本地地址**。
- 支持域名白名单（可配）；请求设超时上限。

### 与 Spec 0005 的关系（含"额度提醒"的解法）

- BYOK 用量**照常记账**（可见、可审计）。
- **不纳入预算硬拦**——用户花的是自己的钱，用他的 key 还限流是荒谬的。
- **余额提醒（尽力覆盖，绝不静默省略）**，按厂商能力分两种情况，都以**显式**方式呈现：
  - **厂商提供余额查询接口** → 去查并展示**真实余额**；低于阈值时给出提醒（只提醒，不拦截）。
  - **厂商不提供该接口** → 界面上**明确写出"该厂商不支持余额查询"**，而不是留空、也不是悄悄拿用量冒充余额。
- 无论能否查到厂商余额，**我方累计用量**都作为**独立维度**照常展示（可审计）。
- 余额查询按厂商做成**可扩展的适配器**；查不到不是失败，但**必须说出来**。
- **口径纪律**：界面与报告须**分别标明**"厂商余额"与"我方统计用量"这两个数字各自的来源，避免后者被误读成前者。

### 开关与回退

- 有配置开关；关闭时**全部走服务端全局配置**（= 今天行为）。
- 用户未配置 BYOK 时，**回落到全局配置**。

## Testing Decisions

- **好测试的标准**：只测**外部行为**（解析出了哪个 LLM、凭据有没有泄漏、危险地址有没有被拒），不测实现细节。
- **缝**（一处新增 + 一处复用）：
  1. **新增**：LLM 工厂、Key 存储、能力探测器——**三者都注入 stub**，全程无网络、无真实厂商。
  2. **复用**：**Spec 0005 的用量记录器**（验证 BYOK 用量被记账、但不被硬拦）。
- **将测的模块**：
  - **回落**——用户未配置 BYOK 时，解析结果等于服务端全局配置（行为与今天一致）。
  - **隔离**——一个用户的配置**不影响**另一个用户。
  - **凭据不回显（硬线）**——读取接口的响应中**不含明文 key**（直接对响应体做断言）；日志与 trace 同样不含。
  - **加密往返**——存取一致；**轮换**后旧凭据失效；**删除**后立即回落全局。
  - **SSRF 防护**——私网 / 回环 / 非 https 的地址被**拒绝**（含单测）。
  - **能力探测**——结果被**缓存**（用 stub 探测器断言调用次数）；探测**失败**时按保守默认且**不默认支持工具**。
  - **代理降级**——模型不支持 tool-calling 时，代理降级为单步回答且**不抛错**。
  - **与 0005**——BYOK 用量被记账，但**不触发硬拦**；超过额度阈值时产生**提醒**。
  - **开关**——关闭时全部走全局配置。
- **测试先例**：`tests/test_api_inference.py`（在边界类注入 stub、不联网）、Spec 0005 定下的 stub 注入风格。

## Out of Scope

- 对**不提供余额接口的厂商**用逆向 / 抓包等非常规手段去推算余额——查不到就明说，不硬凑。
- 用户自带**嵌入 / 重排**模型（BYOK 只管生成）。
- 多 key 的**负载均衡与故障转移**。
- key 的审计日志与合规报表。
- **本地大模型**（6G 显存跑不动，见 README）。
- 多代理 / 微调 / 多模态 / CRUD-RAG。

## Further Notes

- **这是 ROADMAP 的最后一项**：完成本 spec 后，整条 ROADMAP（README → P0/P1/P2a/P2b/P2c → Q9i/Q9ii）**全部有 spec 覆盖**。
- **与已放弃的 Q9ii 的关系**：BYOK **取代**了"一键私有化部署 / 数据不出内网"的对外叙事——把"**多模型可选**"做成真实产品能力，而不是把"私有化"当卖点讲。私有 GPU 节点仍可自用，但不再对外承诺。
- **结构影响**：LLM 从**全局单例**变为**按请求解析**，是本 spec 最主要的架构改动，也是唯一有回归风险的地方——因此"未配置 BYOK 时行为完全一致"被写成硬要求与首要测试项。
- **三条安全硬线**：加密落库、从不回显、私网禁入。三者都是"做错了会真出事"的项，不可打折。
- **余额提醒的口径（2026-09-10 定）**：**尽力覆盖**——厂商有余额接口就查真实余额并提醒；没有就**显式写明"该厂商不支持余额查询"**。无论哪种，我方累计用量都独立展示。**不允许静默省略**：查不到必须说出来，而不是悄悄拿用量冒充余额。
- **发布**：本环境无 `gh`，spec 先落 `docs/specs/`；作者在本机 `gh` 登录后 `gh issue create` 发布并打 `ready-for-agent` 标签（同 0001–0005）。
