# Spec 0003 — 上下文压缩（会话摘要 + 工具结果清理）

> 词汇遵循 [CONTEXT.md](../CONTEXT.md)（会话 / 消息 / 引用 / 忠实度 / 黄金集）。
> 对应 [ROADMAP.md](../ROADMAP.md) 的 **P2a**（顺序 #4 中除 MCP 外的另一半）。
> 发布目标：GitHub issue，标签 `ready-for-agent`。

## Problem Statement

作为项目作者，上下文有两个方向同时失控，而我对它**没有任何度量**：

- **多轮问答**：历史目前是被**硬截断**的——只保留最近几轮，更早的对话直接丢弃。用户会明显感觉到"前面明明说过的，它又不记得了"。
- **反过来全带上**：token 与费用随轮数线性膨胀，延迟上升，早晚撞上模型上下文窗口。而撞上窗口时**系统不会优雅降级，只会报错或静默截断**。
- **代理链路（Spec 0002）更糟**：每一步工具都会往上下文里塞回检索到的整块文本，几轮之后光工具输出就吃掉大半预算——而这些内容里，很多**已经被引用过、不再需要全文**。

于是两头都难受：要么丢信息，要么烧 token。而且因为**没有 token 计数**，我既说不清浪费了多少，也无法证明任何优化真的有效——"降了多少"只能靠嘴说。

## Solution

给"上下文装配"加一层**预算控制**，并让它**可度量**：

- **会话摘要**：超出预算的更早对话压成一段**持久化的滚动摘要**，随会话推进增量更新；最近若干轮仍保留原文。摘要在**未摘要的尾部再次超预算时**才重算一次，之后复用。
- **工具结果清理**：代理循环里，**已被引用过**的工具结果收缩为**元信息**（chunk_id / 文档 / 页码 / 首部片段），未被引用的保留到本轮结束。
- **token 用与生成模型同族的真实分词器计数**，报告给出**token 降幅**。
- **两条保真红线**：① **枚举类查询**（系统刻意注入大量块以便列全）**豁免压缩**；② 已被引用的来源原文不得被丢到无法回溯。
- **降幅必须与质量一起报**：以 **Spec 0001 的评测核心**跑黄金集，确认**事实命中没有下降**——只降 token 而降出错误答案，不算数。

## User Stories

1. 作为项目作者，我想让长对话**不再硬截断**历史，以便用户不会遇到"前面说过的它不记得了"。
2. 作为项目作者，我想让更早的对话被**压成摘要**而不是丢弃，以便关键信息以更小的代价保留下来。
3. 作为项目作者，我想让摘要**随会话增量演进**而不是每轮重算，以便不把省下的 token 又花回摘要上。
4. 作为项目作者，我想用**真实分词器**而非字数估算来数 token，以便"降幅"这个数字可信、可对外讲。
5. 作为项目作者，我想看到**压缩前后的 token 对比**，以便量化这次压缩到底省了多少。
6. 作为项目作者，我想让**事实命中不下降**作为压缩的验收条件，以便不会"降 token 降出错误答案"。
7. 作为项目作者，我想用**同一套评测核心**跑压缩前后，以便两组数字可比、评测代码不用改。
8. 作为项目作者，我想让**枚举类查询豁免压缩**，以便"列出所有表格/公式"这类列举不会因压缩而漏项。
9. 作为项目作者，我想让**已被引用的来源原文保持可回溯**，以便引用仍能定位到原文片段。
10. 作为项目作者，我想让代理循环里**已被引用过的工具结果收缩为元信息**，以便多步推理不把预算耗在已经用掉的内容上。
11. 作为项目作者，我想让**尚未被引用**的工具结果保留到本轮结束，以便代理还能据它继续推理。
12. 作为项目作者，我想给上下文设一个**可配的预算**，以便按模型窗口与实际费用调节。
13. 作为项目作者，我想让预算与**输出上限**是两个独立概念，以便不会把"能写多长"和"能读多少"搞混。
14. 作为项目作者，我想在 token 计数器**不可用时明确知道**，以便不会拿到一个静默降级的假数字。
15. 作为项目作者，我想让摘要**落库到会话**，以便刷新或重启后长对话的上下文不回到起点。
16. 作为使用者，我想在长对话里继续问而**不被要求重复前提**，以便交流自然。
17. 作为使用者，我想在系统**记不住**时被明确告知，而不是收到一个基于残缺上下文的自信错误答案。
18. 作为使用者，我想让回答的**引用仍然准确**，以便压缩不会牺牲"可追溯到原文"这条底线。
19. 作为企业使用方，我想看到**单次问答的 token 用量与降幅**，以便评估成本。
20. 作为企业使用方，我想确认压缩**不会让系统编造**，以便长对话下仍然可信。
21. 作为面试官 / 招聘方，我想看到**降幅与质量并列的数字**，以便判断这是真优化还是把上下文砍掉换来的虚假收益。
22. 作为面试官 / 招聘方，我想看到**明确的口径**（分词器 / 预算 / 触发条件），以便这些数字可信、可复现。
23. 作为项目作者，我想让压缩**默认不改变既有回答行为**（开关可关），以便出问题能一键退回。
24. 作为项目作者，我想让测试**不依赖真实分词器与真实 LLM**，以便确定性、可进 CI。

## Implementation Decisions

### 组件边界

- **上下文预算装配**：一个纯函数，输入（历史消息、工具结果、预算、分词器、摘要器），输出（摘要文本、保留的消息、丢弃与收缩的统计）。它**不自己构造 LLM、也不自己构造分词器**——两者都从外部注入。
- **摘要器**：把一段对话压成摘要的能力，独立于 LLM 抽象之外单独注入；默认（Fake）实现返回固定摘要，使依赖方在测试与演示模式下**确定性**。
- **分词器**：token 计数能力，同样从外部注入。真实实现使用**与生成模型同族的真实分词器**（Qwen 系，惰性加载并缓存），而非字数估算。
- **滚动摘要的持久化**：会话实体新增两样东西——摘要文本，以及"已摘要到哪一条"的游标。摘要**只在未摘要的尾部再次超预算时**重算一次并回写，之后每轮复用。

### 触发与预算

- **预算是一个独立配置**（读取侧），与输出上限（生成侧 `llm_max_tokens`）**是两个概念**，不得混用。
- **触发条件**：未摘要尾部的 token 数超过预算才压缩；未超则原样透传（零额外开销）。
- 压缩后仍**保留最近若干轮原文**，以保证指代消解仍有近期上下文可用。

### 两条保真红线（豁免）

- **枚举意图豁免**：命中"枚举某类内容"的查询，其刻意注入的大批块**不参与压缩**——否则"列出所有表格/公式"会漏项。
- **已引用来源豁免**：被引用过的来源，其原文必须保持**可回溯到片段**。因此工具结果收缩**只允许丢弃全文**，必须保留 chunk_id、文档名、页码与首部片段。

### 工具结果清理

- 代理循环内：**已被引用**的工具结果收缩为元信息；**尚未被引用**的保留到本轮结束，之后收缩。
- 这一半**只对代理循环（Spec 0002）有意义**；对现有确定性问答链路不产生行为变化。

### 计数与报告

- token 计数一律用**真实分词器**；分词器不可用时，该指标**标记为不可用**，**不得静默回退到字数估算**（沿用 Spec 0001 "缺件不得静默给假数字"的原则）。
- 报告给出：压缩前 token / 压缩后 token / **降幅**，并与 **Spec 0001 的事实命中**并列呈现。

### 开关与兼容

- 压缩**默认开启**（这正是 P2a 的目的），但提供**关闭开关**一键退回当前的"硬截断最近若干轮"行为；关闭时行为与今天完全一致。
- 关闭开关不改变既有 API 契约。

## Testing Decisions

- **好测试的标准**：只测**外部行为**（给定上下文与预算，装配后保留了什么、省了多少），不测实现细节。
- **缝**（一处新增 + 一处复用）：
  1. **新增**：上下文预算装配——注入 **stub 摘要器 + stub 分词器**，全程无网络、无真实 LLM、结果确定。
  2. **复用**：**Spec 0001 的评测核心**（`answer_fn` 缝）——用来证明"压缩后事实命中未下降"，P2a 不新增评测代码。
- **将测的模块**：
  - 预算装配——**未超预算时原样透传**（零压缩、零额外调用）；超预算时触发摘要并保留最近若干轮。
  - 滚动摘要——**增量复用**：第二次调用不重算未变化的部分（用 stub 摘要器的调用次数断言）。
  - 工具结果收缩——已被引用的结果收缩后**仍保留 chunk_id / 文档 / 页码 / 首部片段**；未引用的保留到本轮结束。
  - **豁免路径**——枚举意图的上下文**完全不压缩**（回归：列全表格不因压缩漏项）。
  - **降级诚实性**——分词器不可用时指标标记为**不可用**，而不是回退成估算值。
  - **开关**——关闭压缩时，行为与今天的硬截断完全一致。
- **测试先例**：`tests/test_api_inference.py`（在边界类注入 stub、不联网）、Spec 0001 定下的 "stub 注入 + 断言确定性" 风格。

## Out of Scope

- **跨会话记忆**（从会话抽"事实"存表并召回）——那是 ROADMAP 的 **P2c**，另一件事。
- 语义 / 向量式压缩，或为压缩任务微调模型。
- 改变**检索候选的选择逻辑**（压缩只作用于装配，不改变检索什么）。
- 成本面板 UI —— 那是 ROADMAP 的 **Q9i**。
- 多代理 / 微调 / 多模态 / CRUD-RAG。

## Further Notes

- **与 Spec 0002 的关系**：本 spec 的"工具结果清理"那一半**只对代理循环有意义**，因此切票时应 gate 在 0002 的代理票据（11 代理循环）之后；"会话摘要"那一半对现有确定性链路**独立可用**，可以立刻开工。
- **与 Spec 0001 的关系**：质量护栏**必须**复用 0001 的评测核心。降幅与事实命中**一起报**，专门防止"把上下文砍掉换来的虚假收益"被当成优化成果——这是本 spec 最重要的一条验收纪律。
- **依赖**：真实分词器需在宿主可用（Qwen 系，`transformers` 已在真实依赖清单中）；沙箱内装依赖走 TUNA 镜像。
- **schema 变化**：会话实体新增摘要字段与游标，属**向前兼容的新增列**，不影响既有数据与既有查询。
- **缝的取舍（如实记录）**：本 spec 是 0001 / 0002 / 0003 三份里**最干净的一份**——只新增一个缝（装配函数，两个协作者均注入），端到端度量完全复用 0001，没有引入传输或进程边界。
- **发布**：本环境无 `gh`，spec 先落 `docs/specs/`；作者在本机 `gh` 登录后 `gh issue create` 发布并打 `ready-for-agent` 标签（同 0001 / 0002）。
