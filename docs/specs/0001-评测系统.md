# Spec 0001 — 评测系统(P0)

> 词汇遵循 [CONTEXT.md](../CONTEXT.md)(拒答 / 忠实度 / 黄金集 / 负样本 / 双轨评测)。
> 对应 [ROADMAP.md](../ROADMAP.md) 的 **P0**。发布目标:GitHub issue，标签 `ready-for-agent`。

## Problem Statement

作为项目作者(单人、求职中),我目前只有**小规模自建黄金集(10–15 问)+ 自研判据**,由此得到的"质量数字"**不具业界可比性**,也无法系统回答"**抗幻觉 / 拒答正确 / 延迟**"到底如何;每次改动后**无法快速判断是涨还是退**。面试与简历需要**可信、可比、可复现**的质量证据;企业使用方则需要确信"**问不到时会拒答、不瞎编**"。

## Solution

一套**双轨评测系统**:
- **数据**:领域黄金集(自建)+ 公开基准 **RGB 中文四能力**(噪声鲁棒 / 否定拒绝 / 信息集成 / 反事实鲁棒)。
- **指标**:自研免 LLM 判据(含期望事实 / 页码 / **拒答** / 引用覆盖率)+ **RAGAS 四项**(faithfulness / answer-relevancy / context-precision / recall,judge 固定 **qwen-turbo、temp=0**)+ 检索层(hit@k / recall@k / MRR)+ 延迟(分桶,P50 / P95 / TTFT,3–5 并发)。
- **产出**:**一键运行 → 一页带数字的报告**(报告含指标口径与配置快照)。
- **优先级**:**抗幻觉 + 拒答** 第一,**延迟** 第二。

## User Stories

1. 作为项目作者,我想**一键运行整套评测**,以便得到当前质量的完整数字。
2. 作为项目作者,我想看到**检索层指标**(hit@k / recall@k / MRR),以便定位"检索是否漏了正确答案"。
3. 作为项目作者,我想看到**生成层 RAGAS 四项**,以便判断答案质量。
4. 作为项目作者,我想看到**拒答率**(负样本 + RGB 否定拒绝),以便确认"问不到时不瞎编"。
5. 作为项目作者,我想看到**忠实度 / 引用覆盖率**,以便确认答案"有据可依"。
6. 作为项目作者,我想看到**端到端事实命中 / 页码正确**,以便验证业务可用性。
7. 作为项目作者,我想**对改动前后跑同一套评测并对比**,以便量化"这次是涨还是退"。
8. 作为项目作者,我想看到**延迟分桶**(检索 / 重排 / LLM 各段)与**并发下 P50 / P95 / TTFT**,以便判断性能。
9. 作为项目作者,我想报告**固定 judge 口径与配置快照**,以便数字可复现、可跨时间比较。
10. 作为项目作者,我想用**同一评测核心**评测不同后端(本地 / Fake / 云端)而**不改评测代码**,以便一致地比较。
11. 作为项目作者,我想让评测**不依赖运行中的服务器**(可注入被评测管线),以便离线 / CI 里跑。
12. 作为面试官 / 招聘方,我想看到**可跨项目对比的标准指标**(RAGAS / RGB),以便判断候选人的工程成熟度。
13. 作为面试官 / 招聘方,我想看到**明确的指标口径**,以便信任这些数字。
14. 作为企业使用方,我想(l通过报告)确认系统"**问不到会拒答、不编造**",以便放心使用。
15. 作为企业使用方,我想知道**延迟 / 成本表现**,以便评估可用性。

## Implementation Decisions

- **评测核心做成一注入式纯函数**:`run_eval(goldenset, answer_fn, judge_fn) -> Report`。`answer_fn`(问题 → 答案 + 来源)与 `judge_fn`(LLM 裁判)**从外部注入**,评测核心不耦合服务器、不直接调 LLM。
- **复用现有评测缝**:检索指标复用 `evaluate_retrieval.py` 的 `_index_doc / _rank_lists / _metrics`;端到端判据(含期望事实 / 页码 / 拒答)复用 `evaluate.py` 的逻辑,抽成可注入核心。
- **RGB 只加适配器**:一个 `rgb_loader` 把 RGB 数据转成内部黄金集格式,复用同一个 `run_eval`;不改 RGB 原始数据。
- **判据口径固定**:RAGAS judge = `qwen-turbo`,温度 0;报告写明"RAGAS(judge=qwen-turbo, temp=0)"。
- **指标集**:RAGAS 四项 + 自研(事实命中 / 页码 / 拒答 / 引用覆盖率) + 检索(hit@k / recall@k / MRR) + 延迟(分桶 + 并发 P50/P95/TTFT)。
- **报告**:一页 markdown / 文本,含**所有数字 + 口径 + 配置快照**。
- **阈值只作"目标线"**:例如 faithfulness / 拒答率的目标值写入报告并标红,但**不引入 CI 发版门禁**。
- **不改业务管线**:只新增评测代码;被评测的检索 / 生成通过注入接入。
- **词汇**遵循 `CONTEXT.md`;术语不漂移。

## Testing Decisions

- **好测试的标准**:只测**外部行为**(指标计算是否正确),不测实现细节。
- **测法**:注入 **stub `answer_fn` + stub `judge_fn`**(返回固定值)→ 断言指标计算**确定性、无网络、无 LLM**。
- **将测的模块**:评测核心 `run_eval`(指标计算)、RGB 适配器(格式转换)、报告生成(含数字与口径)。
- **测试先例**:`tests/test_api_inference.py`(monkeypatch 注入风格)、`tests/test_prod.py`(无外部依赖)。

## Out of Scope

- 多代理 / 微调 / 多模态评测。
- CI 发版门禁(评测保持"一键脚本 + 报告")。
- CRUD-RAG 基准。
- 修改检索 / 生成管线本体。
- 线上实时 / 持续评测。
