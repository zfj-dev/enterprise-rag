# Spec 0004 — 跨会话记忆（最小）

> 词汇遵循 [CONTEXT.md](../CONTEXT.md)（会话 / 消息 / 引用 / 忠实度）。
> 对应 [ROADMAP.md](../ROADMAP.md) 的 **P2c**。
> 发布目标：GitHub issue，标签 `ready-for-agent`。

## Problem Statement

作为项目作者，我的系统目前是**无状态问答**：一次会话结束，里面的一切就都忘了。

于是用户在每个新会话里都得**重新交代前提**——"我们公司是……"、"上次说的那份报表……"、"按我上次讲的口径"。系统明明**见过**这些信息，只是会话一断就全丢。

这**不是检索问题**：文档在、模型也够强，缺的是"**跨会话保留用户已经告知过的事实**"。

而直接拿历史全量顶上去也不行：那会把大量无关内容灌进每一次请求（Spec 0003 处理的是**会话内**压缩，它救不了跨会话——一开新会话，历史就是空的）。

还有一条不能破的纪律：记忆是**"用户说过的话"**，不是**"文档里的依据"**。它绝不能被当成回答的**来源**——否则引用溯源与"no source → no claim"会一起烂掉。

## Solution

加一层**最小可用的跨会话记忆**：

- 每轮问答**完成后异步抽取**"事实"并落库，**按用户隔离**。
- 新会话提问时，按相似度**召回**少量相关事实，作为一块**独立的「已知信息」**注入 prompt。
- **记忆不可作为引用来源**：回答的依据仍必须来自文档；记忆只用于理解问题、消歧与个性化，**不产生"来源"**。
- 用户可**查看与删除**自己的记忆（隐私的最小要求）。
- 产出一个**跨会话召回示例**：会话 A 告知一个事实，会话 B 能据此正确回应。

## User Stories

1. 作为使用者，我想在**新会话里不必重新交代背景**，以便直接接着上次的上下文问。
2. 作为使用者，我想让系统记住我**告知过的事实**（我的角色、我关心的项目、我习惯的口径），以便回答更贴合我。
3. 作为使用者，我想让被记住的只是**我确实说过的事实**，而不是模型自己的猜测或文档内容，以便记忆不会"记歪"。
4. 作为使用者，我想让记忆**安静地生效**，不必手动"保存"或"开启记忆"，以便无感。
5. 作为使用者，我想能**看到系统记住了我什么**，以便心里有数。
6. 作为使用者，我想能**删除**某条记忆，以便纠正错误或收回不想被记住的内容。
7. 作为使用者，我想删除**立即生效**，以便下一个问题就不再受它影响。
8. 作为使用者，我想在系统**没有相关记忆**时不受打扰，以便不会每次都被塞一堆无关背景。
9. 作为项目作者，我想让事实抽取**在回答完成之后异步进行**，以便抽取失败或变慢都不影响用户拿到回答。
10. 作为项目作者，我想让抽取器与记忆存储**从外部注入**，以便测试确定性、可换实现。
11. 作为项目作者，我想让召回**按相似度取 top-k 且有上限**，以便不会把记忆堆爆上下文。
12. 作为项目作者，我想让记忆**作为独立一路注入**，以便它不进入检索候选池。
13. 作为项目作者，我想让记忆**绝不出现在"来源"里**，以便引用契约与"no source → no claim"不被破坏。
14. 作为项目作者，我想让引用校验的输入**仍然只有文档来源**，以便记忆不会让"有依据"的判定变松。
15. 作为项目作者，我想让记忆**按用户隔离**，以便看不到别人的记忆。
16. 作为项目作者，我想让召回的权限**按用户下推**，以便与现有检索时的权限过滤同源。
17. 作为项目作者，我想让记忆的注入与 **Spec 0003 的上下文预算**能并存，以便不会出现"省了 token 又被记忆塞满"。
18. 作为项目作者，我想让记忆功能**有开关且默认不破坏现有回答**，以便出问题能一键退回。
19. 作为项目作者，我想有一个**跨会话召回示例**（会话 A 告知 → 会话 B 正确回应），以便提交物里能演示。
20. 作为项目作者，我想用 **Spec 0001 的评测核心**验证记忆**没有引入幻觉**（引用忠实度不下降），以便"记得更多"不以"编得更多"为代价。
21. 作为项目作者，我想让测试**不依赖真实 LLM 与真实库**，以便确定性、可进 CI。
22. 作为企业使用方，我想确认记忆**不会被当成答依据**、且**能按人删除**，以便放心在内网给人用。
23. 作为面试官 / 招聘方，我想看到记忆是**按用户隔离、且不污染引用**的，以便判断这是有边界的设计而非演示品。

## Implementation Decisions

### 组件边界

- **事实抽取器**：把一轮问答压成若干"事实"的能力，从外部注入（默认 Fake 返回空集，保证演示与测试确定性）。
- **记忆存储**：按用户存取与删除事实的能力，从外部注入（默认内存实现，便于测试隔离）。
- **召回**：按相似度取 top-k，复用现有**嵌入缝**；不新增相似度算法。

### 抽取

- **时机**：每轮问答**完成之后**异步进行。抽取失败或超时一律**旁路**——不得影响用户拿到回答，也不得阻塞下一个问题。
- **抽什么**：**只抽"用户告知的、可跨会话复用的事实"**（例如身份/角色、偏好、所在项目与业务背景、约定的口径）。
- **明确不抽**：**文档内容**（那是检索的职责）、以及**模型自己生成的回答**（防止把一次幻觉固化成"事实"）。
- 最小版**只追加**，不做冲突消解与时效判定（见 Out of Scope）。

### 召回与注入

- 按相似度取 **top-k 且有上限**；**无相关记忆时零注入**（不塞空块、不占预算）。
- 注入形态是一块**独立的「已知信息」**，与【参考资料】**分开呈现**。
- **不可引用是硬约束**：记忆**不进入**检索候选池，也**不进入 `sources`**；引用校验的输入**只有文档来源**。
- 与 Spec 0003 并存：记忆注入同样受**上下文预算**约束，不得因记忆把预算撑爆。

### 隔离与隐私

- 记忆**按用户隔离**；存储、召回、删除**全部按用户下推过滤**（与现有"检索时权限过滤"同源）。
- 提供**列出**与**删除**某条记忆的能力；删除**立即生效**——后续召回不得再包含它。

### 存储

- 新增一张表：事实文本、所属用户、来源（会话与消息）、创建时间，以及（可选的）向量列。
- 属**新增表**，不改动既有表结构与既有查询。

### 开关与兼容

- 记忆有**配置开关**；关闭时行为与今天完全一致，既有 API 契约不变。

## Testing Decisions

- **好测试的标准**：只测**外部行为**（记住了什么、召回了什么、有没有被当成来源），不测实现细节。
- **缝**（一处新增 + 两处复用）：
  1. **新增**：事实抽取器与记忆存储——注入 **stub 抽取器 + stub 存储**，全程无网络、无真实 LLM、结果确定。
  2. **复用**：**嵌入缝**（召回相似度）与 **Spec 0001 的评测核心**（验证引用忠实度未下降）。
- **将测的模块**：
  - **抽取边界**——只抽"用户告知的事实"；**文档内容与模型回答都不被抽**（用 stub 输入断言输出集合）。
  - **隔离**——按用户召回：另一个用户的事实**取不到**。
  - **零注入**——无相关记忆时不产生任何注入块、不占预算。
  - **不可引用（核心回归）**——记忆出现在 prompt 中，但**不出现在 `sources` 里**，且**不改变引用校验的结论**（同一条答案，有/无记忆时 `has_sources` 判定一致）。
  - **删除即刻生效**——删除后同一问题不再召回该条。
  - **失败旁路**——抽取器抛错时，回答仍正常返回、不抛穿。
  - **跨会话示例**——会话 A 告知一个事实，会话 B 能召回并据此正确回应。
  - **与 0003 并存**——记忆注入受上下文预算约束，不撑爆预算。
- **测试先例**：`tests/test_api_inference.py`（在边界类注入 stub、不联网）、Spec 0001 定下的 "stub 注入 + 断言确定性" 风格。

## Out of Scope

- 事实的**冲突消解与时效性**（用户改口、事实过期怎么办）——最小版**只追加**。
- 记忆的**编辑 UI**（本 spec 只做列出与删除）。
- **跨用户共享**记忆。
- **把记忆并入检索池当作来源**——明确不做（会破坏引用契约）。
- 引入长期记忆框架（mem0 / RAPTOR 之类）。
- 记忆的加密与审计日志。
- 多代理 / 微调 / 多模态 / CRUD-RAG。

## Further Notes

- **与 Spec 0003 的边界（写死，避免两份 spec 打架）**：0003 是**会话内**压缩（历史 → 摘要，不跨会话）；0004 是**跨会话**记忆（抽事实存表，不压缩单次上下文）。二者不重叠、不互相侵入。
- **与 Spec 0002 的关系**：代理循环原则上也可以消费记忆，但本 spec **不要求**——保持"最小"。
- **与 Spec 0001 的关系**：用评测核心验证"引用忠实度不下降"，专门防止"**记得更多 = 编得更多**"。
- **存储**：新增一张表，**向前兼容**，不改既有表与查询。
- **发布**：本环境无 `gh`，spec 先落 `docs/specs/`；作者在本机 `gh` 登录后 `gh issue create` 发布并打 `ready-for-agent` 标签（同 0001 / 0002 / 0003）。
